# denpa-dt295-patches

denpa 本体は上流（`danything/denpa`）のまま使い、DT295 チューナー向けの改造だけを
パッチとして管理するリポジトリ。

dt295-agent と同じ思想 — 上流を直接 fork せず、差分だけを持つ — で、
denpa の頻繁なアップデートに追従しやすくする。

## 方式

```
上流 denpa (tag)  →  patches/*.patch を順に適用  →  ビルド / デプロイ
```

- denpa 本体のソースはこのリポジトリに置かない（上流から取得する）
- 改造は `patches/` の差分ファイルだけを管理する
- 上流の新しいバージョンが出たら `upstream.version` を更新し、
  パッチが衝突したときだけ `scripts/rebase.sh` で直す

## 改造内容（パッチの論点）

| パッチ | 内容 |
|---|---|
| `0001-dt295-customizations.patch` | DT295 向けの全改造（下記） |

1 枚の統合パッチに含まれる論点：

- **チューナー画質プリセット** — コーデック選択メニューに DT295 オンボード変換の
  プリセット（MPEG-2 パススルー / H.264 各解像度）を並べる
- **H.264 コピー経路** — チューナー出力の H.264 を再エンコードせずコピーする
- **平文 http エージェント** — DT295 エージェント（平文 http）を許可する
- **CS 安定化** — 字幕失敗時のリトライ、壊れたパケットの破棄、PID マップを任意に
- **DT295 mAgicVISION ランタイム** — 常駐セッションの開始前停止、v2 ランタイム
- **`--transcode` プリセット API** — `/api/tuner-preset`、`base path` 対応

## 追従済み上流バージョン

`upstream.version` を参照（現在: `2.51.0`）。

## 使い方

```bash
# 上流を取得してパッチを適用 → ビルド用ツリーを作る
./scripts/apply.sh /path/to/output

# 上流を新しいバージョンに上げる（パッチが衝突したら手で直す）
./scripts/rebase.sh 2.52.0
```

## 既存 fork との関係

- 既存の `rk2kk/denpa` fork は当面残す（移行が終わるまで並行運用）
- このリポジトリが安定したら fork をアーカイブする予定

## ライセンス

元の denpa に準ずる（AGPL-3.0）。
